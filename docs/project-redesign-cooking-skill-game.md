# 料理スキルアップゲーム - プロジェクト設計書

**プロジェクト名**: Yamtune v2.0 - あなたのレベル100を目指す料理スキルアップゲーム
**作成日**: 2025年12月14日
**ステータス**: 設計フェーズ

---

## 🎯 プロジェクト概要

### コンセプト
> 「料理スキルをレベル100にする、あなただけの成長ストーリー」

一人暮らしの20〜40代向けに、ゲーミフィケーションを取り入れた料理スキルアップアプリ。20週間（約4ヶ月）で「あなた自身のレベル100」を達成し、料理の基礎を習得しながら、栄養バランスの取れた時短料理を作れるようになる物語形式の成長体験を提供します。

### ビジョン
「料理が苦手」「何を作ればいいかわからない」という一人暮らしの悩みを、RPGのようなレベルアップ体験に変換。継続することで確実にスキルが上がる実感を得られ、料理を「義務」から「楽しい習慣」に変える。

---

## 🎮 ゲーミフィケーション設計

### レベルシステム

#### 基本ルール
- **総レベル**: 1 → 100
- **成長期間**: 20週間（約4ヶ月）
- **週次成長**: レベル+5 / 週
- **条件**: 平日5日分の料理を完了

#### レベル帯別の成長フェーズ

| レベル帯 | フェーズ名 | 期間 | 習得内容 | 料理難易度 |
|---------|-----------|------|---------|-----------|
| Lv 1-20 | 🌱 見習い料理人 | Week 1-4 | 基本の調理器具、切り方、火加減 | 超簡単（3工程以内） |
| Lv 21-40 | 🔥 駆け出し料理人 | Week 5-8 | 味付けの基本、栄養バランス | 簡単（5工程以内） |
| Lv 41-60 | 👨‍🍳 一般料理人 | Week 9-12 | 時短テクニック、作り置き | 中級（7工程以内） |
| Lv 61-80 | ⭐ 熟練料理人 | Week 13-16 | アレンジ力、食材活用 | 中上級（自由度高） |
| Lv 81-100 | 🏆 マスター料理人 | Week 17-20 | オリジナルレシピ創作 | 上級（完全自由） |

### 経験値（XP）システム

#### XP獲得方法
| アクション | XP | 説明 |
|-----------|-----|------|
| 料理完了 | +100 XP | 推奨レシピを完了 |
| 調理記録投稿 | +50 XP | 写真＋コメント投稿 |
| 新しい調理法習得 | +200 XP | 初めての調理法をマスター |
| 週次目標達成 | +500 XP | 週5日達成でボーナス |
| 作り置き活用 | +80 XP | 作り置きレシピを活用 |
| 食材使い切り | +150 XP | 冷蔵庫の食材を完全消費 |

#### レベルアップ必要XP
```
必要XP = 1000 + (現在レベル × 50)
例:
Lv 1→2: 1,050 XP
Lv 10→11: 1,500 XP
Lv 50→51: 3,500 XP
```

週5日料理 = 500 XP (基本) + 500 XP (ボーナス) = 1,000 XP/週
→ 平均的に週1レベルアップ = 約5レベル/週の成長

### バッジ・実績システム

#### 基本バッジ
- 🔪 **包丁マスター**: 野菜を10種類以上切った
- 🍳 **フライパンの達人**: 炒め物を20回完了
- 🥘 **煮込み職人**: 煮込み料理を10回完了
- ⏱️ **時短の魔術師**: 15分以内の料理を30回完了
- 🌈 **栄養バランサー**: 5大栄養素バランスの良い料理を20回
- 🔁 **作り置きの賢者**: 作り置きを5週連続活用

#### 週間チャレンジバッジ
- 🔥 **パーフェクトウィーク**: 週5日完璧にクリア
- 💪 **継続の力**: 3週連続達成
- 🎯 **月間マスター**: 4週連続達成

#### 特殊実績
- 🎖️ **初めての一品**: 初レシピ完了
- 🌟 **中間地点**: レベル50到達
- 👑 **レベル100達成**: 最終ゴール

#### キャラクター設定

## 🎨 コア機能設計

### 1. オンボーディング（初期設定）

#### 設定項目
1. **基本情報**
   - 料理経験レベル（超初心者 / 初心者 / 中級者）
   - 目標（時短 / 栄養 / 節約 / スキルアップ）

2. **保有調理器具チェックリスト**
   ```
   必須:
   - [ ] 包丁
   - [ ] まな板
   - [ ] フライパン
   - [ ] 鍋
   - [ ] ボウル

   あると便利:
   - [ ] 電子レンジ
   - [ ] オーブン
   - [ ] 炊飯器
   - [ ] ホットプレート
   - [ ] ブレンダー
   - [ ] フードプロセッサー
   ```

3. **可処分時間設定**
   - 平日調理可能時間: 15分 / 30分 / 60分
   - 休日調理可能時間: 30分 / 60分 / 120分
   - 作り置き対応: する / しない

4. **食の制約・好み**
   - アレルギー食材
   - 苦手な食材（3つまで）
   - 好きな料理ジャンル（和洋中）

### 2. 週次カリキュラム自動生成

#### システムの流れ
```
1. ユーザーの現在レベルを確認
2. 該当週のスキルテーマを決定
3. 保有器具・可処分時間・食の制約を考慮
4. 平日5日分のレシピを自動生成
5. 栄養バランスを自動調整
6. 買い物リスト生成
```

#### カリキュラム例: Week 1 (Lv 1-5)
```
月曜: 目玉焼き丼（調理時間: 10分）
  スキル: 卵の焼き方、火加減の基本

火曜: 野菜炒め（調理時間: 15分）
  スキル: 野菜の切り方、炒める順番

水曜: 味噌汁＋おにぎり（調理時間: 15分）
  スキル: 出汁の取り方、味噌の溶き方

木曜: パスタ（トマトソース）（調理時間: 20分）
  スキル: パスタの茹で方、ソースの絡め方

金曜: 鶏の照り焼き（調理時間: 20分）
  スキル: 肉の焼き方、タレの黄金比
```

### 4. 作り置き対応システム

#### 作り置き提案タイミング
- ユーザーが「平日時間ない」と設定
- 週末（土日）に調理時間がある場合

#### 作り置きレシピ例
```
日曜の作り置き（90分）:
1. 鶏ハム（月・水のタンパク源）
2. きんぴらごぼう（火・木の副菜）
3. ミートソース（水のパスタ用）

→ 平日は温め直し＋アレンジで完成
```

#### 作り置き活用フロー
```
日曜: 作り置き調理 → +500 XP
月曜: 作り置き活用 → +80 XP
火曜: 作り置き活用 → +80 XP
...
```

## 🗂️ データモデル設計

### 主要テーブル

#### 1. users（ユーザー）
```sql
CREATE TABLE users (
  id UUID PRIMARY KEY,
  email VARCHAR NOT NULL UNIQUE,
  username VARCHAR NOT NULL,
  current_level INT DEFAULT 1,
  total_xp INT DEFAULT 0,
  cooking_experience VARCHAR, -- beginner/intermediate/advanced
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);
```

#### 2. user_settings（ユーザー設定）
```sql
CREATE TABLE user_settings (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  weekday_cooking_time INT, -- 分
  weekend_cooking_time INT, -- 分
  meal_prep_enabled BOOLEAN DEFAULT false,
  allergies TEXT[], -- アレルギー食材配列
  disliked_foods TEXT[], -- 苦手な食材配列
  preferred_cuisines TEXT[], -- 好きなジャンル
  updated_at TIMESTAMP
);
```

#### 3. user_equipment（保有調理器具）
```sql
CREATE TABLE user_equipment (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  equipment_name VARCHAR NOT NULL, -- knife, pan, oven, etc.
  has_equipment BOOLEAN DEFAULT false,
  added_at TIMESTAMP
);
```

#### 4. weekly_curriculum（週次カリキュラム）
```sql
CREATE TABLE weekly_curriculum (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  week_number INT NOT NULL, -- 1-20
  target_level_start INT, -- 開始レベル
  target_level_end INT, -- 終了レベル
  skill_theme VARCHAR, -- 今週のスキルテーマ
  status VARCHAR, -- not_started / in_progress / completed
  created_at TIMESTAMP
);
```

#### 5. daily_recipes（デイリーレシピ）
```sql
CREATE TABLE daily_recipes (
  id UUID PRIMARY KEY,
  curriculum_id UUID REFERENCES weekly_curriculum(id),
  day_of_week INT, -- 1=月, 2=火, ...
  recipe_name VARCHAR NOT NULL,
  recipe_description TEXT,
  cooking_time INT, -- 分
  difficulty VARCHAR, -- easy/medium/hard
  skill_learned VARCHAR, -- 習得スキル
  ingredients JSONB, -- 材料リスト
  steps JSONB, -- 手順
  nutritions JSONB, -- 栄養情報
  image_url VARCHAR,
  video_url VARCHAR,
  is_meal_prep BOOLEAN DEFAULT false,
  created_at TIMESTAMP
);
```

#### 6. cooking_logs（調理記録）
```sql
CREATE TABLE cooking_logs (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  recipe_id UUID REFERENCES daily_recipes(id),
  completed_at TIMESTAMP,
  user_photo_url VARCHAR,
  taste_rating INT, -- 1-5
  difficulty_rating VARCHAR, -- easy/normal/hard
  notes TEXT,
  xp_earned INT,
  created_at TIMESTAMP
);
```

#### 7. user_progress（ユーザー進捗）
```sql
CREATE TABLE user_progress (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  level INT NOT NULL,
  xp INT NOT NULL,
  total_recipes_completed INT DEFAULT 0,
  consecutive_days INT DEFAULT 0,
  longest_streak INT DEFAULT 0,
  updated_at TIMESTAMP
);
```

#### 8. badges（バッジマスター）
```sql
CREATE TABLE badges (
  id UUID PRIMARY KEY,
  badge_name VARCHAR NOT NULL,
  badge_icon VARCHAR,
  description TEXT,
  condition_type VARCHAR, -- recipe_count/skill_count/streak etc.
  condition_value INT,
  created_at TIMESTAMP
);
```

#### 9. user_badges（ユーザー獲得バッジ）
```sql
CREATE TABLE user_badges (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  badge_id UUID REFERENCES badges(id),
  earned_at TIMESTAMP
);
```

#### 10. learned_skills（習得スキル）
```sql
CREATE TABLE learned_skills (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  skill_name VARCHAR NOT NULL, -- "野菜の切り方", "肉の焼き方"
  skill_category VARCHAR, -- cutting/cooking/seasoning
  mastery_level INT DEFAULT 1, -- 1-5
  times_practiced INT DEFAULT 0,
  learned_at TIMESTAMP,
  updated_at TIMESTAMP
);
```

#### 11. shopping_lists（買い物リスト）
```sql
CREATE TABLE shopping_lists (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  curriculum_id UUID REFERENCES weekly_curriculum(id),
  items JSONB, -- [{name, quantity, category, checked}]
  total_estimated_cost INT,
  created_at TIMESTAMP,
  completed_at TIMESTAMP
);
```

#### 12. pantry_items（冷蔵庫在庫）
```sql
CREATE TABLE pantry_items (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  item_name VARCHAR NOT NULL,
  quantity VARCHAR,
  expiration_date DATE,
  category VARCHAR,
  added_at TIMESTAMP,
  used_at TIMESTAMP
);
```

## 🚨 リスク＆対策

### リスク1: ユーザーが挫折する
**対策**:
- 難易度を段階的に上げる（Lv 1は超簡単）
- AIコーチが励まし＆サポート
- 失敗してもXPが減らない設計
- レベルダウンなし（前向きな設計）

### リスク2: レシピ生成の質が低い
**対策**:
- プロンプトエンジニアリング徹底
- レシピデータベースを事前準備（AI生成補助）
- ユーザーフィードバックで改善

### リスク3: 継続率が上がらない
**対策**:
- プッシュ通知で習慣化促進
- 週次リマインダー（日曜夜）
- ソーシャル要素（友達と競争）Phase 2で追加

### リスク4: 開発期間オーバー
**対策**:
- MVPスコープ厳守
- Phase 2以降の機能は後回し
- アジャイル開発で段階リリース
